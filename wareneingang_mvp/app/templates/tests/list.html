Testfälle

Diese Seite dokumentiert zentrale Testfälle für den Prototypen. Die Testfälle orientieren sich an den wichtigsten Statusflüssen, Buchungsregeln, Retouren und Lieferantenrechnungen.

Wareneingang und Statusfluss

Nr. Testfall Schritte Erwartetes Ergebnis
WE-01 Wareneingang erfassen Rolle Lager wählen → Bestellung öffnen → Wareneingang erfassen → Menge eintragen → speichern Wareneingang wird mit Status ERFASST angelegt. Ein Ereignis wird im Ereignisprotokoll gespeichert.
WE-02 Prüfung starten Wareneingang im Status ERFASST öffnen → Prüfung starten Status wechselt auf IN_PRUEFUNG.
WE-03 Direkte Buchung nur bei Ware OK Wareneingang mit Zustand WARE_OK erfassen → Prüfung starten → Wareneingang buchen Status wechselt auf WARENEINGANG_GEBUCHT. Lagerbestand wird erhöht. Bestandsbewegung mit Bewegungsart IN wird geschrieben.
WE-04 Buchung mit Abweichung verhindern Wareneingang mit Zustand BESCHAEDIGT oder PRUEFUNG_AUSSTEHEND erfassen → Prüfung starten → Wareneingang buchen Buchung wird blockiert. Es erscheint eine Fehlermeldung. Lagerbestand bleibt unverändert.

Abweichung und Klärung

Nr. Testfall Schritte Erwartetes Ergebnis
AB-01 Abweichung dokumentieren Wareneingang mit beschädigter Ware erfassen → Prüfung starten → Mit Abweichung markieren Status wechselt auf MIT_ABWEICHUNG.
AB-02 In Klärung geben Wareneingang mit Status MIT_ABWEICHUNG öffnen → In Klärung geben Status wechselt auf IN_KLAERUNG. Der Fall erscheint im Management-Dashboard.
AB-03 Nach Klärung buchen Rolle Management wählen → Wareneingang in Klärung öffnen → Zustand auf WARE_OK setzen → Klärung speichern → Nach Klärung buchen Status wechselt auf WARENEINGANG_GEBUCHT. Lagerbestand wird erhöht.
AB-04 Retoure veranlassen Rolle Management wählen → Wareneingang in Klärung öffnen → Retoure veranlassen Status wechselt auf RETOURE_VERANLASST. Lagerbestand wird nicht erhöht. Eine Retourenmeldung wird erstellt.

Bestand, Storno und Bewegungen

Nr. Testfall Schritte Erwartetes Ergebnis
BS-01 Bestandsbewegung IN prüfen Wareneingang buchen → Bestandsbewegungen öffnen Eine Bewegung mit Bewegungsart IN wird angezeigt.
BS-02 Gebuchten Wareneingang stornieren Rolle Management wählen → gebuchten Wareneingang ohne Rechnung öffnen → Gebuchten Wareneingang stornieren Status wechselt auf STORNIERT. Lagerbestand wird reduziert. Bestandsbewegung mit Bewegungsart OUT wird geschrieben.
BS-03 Storno mit vorhandener Rechnung verhindern Gebuchten Wareneingang mit bereits erfasster Lieferantenrechnung öffnen → Storno versuchen Storno wird blockiert. Das System zeigt eine Meldung, dass bereits eine Rechnung existiert.

Lieferantenrechnung

Nr. Testfall Schritte Erwartetes Ergebnis
LR-01 Rechnung nur bei gebuchtem Wareneingang Lieferantenrechnung zu einem nicht gebuchten Wareneingang erfassen Erfassung wird blockiert.
LR-02 Lieferantenrechnung erfassen Gebuchten Wareneingang öffnen → Lieferantenrechnung erfassen → Positionen mit Preis, Rabatt und MwSt speichern Rechnung wird mit Status ERFASST gespeichert. Netto, MwSt und Brutto werden automatisch berechnet.
LR-03 Rechnung an Buchhaltung übermitteln Rechnung öffnen → An Buchhaltung übermitteln Status wechselt auf AN_BUCHHALTUNG_UEBERMITTELT. Übermittlungsdatum wird gesetzt.
LR-04 Doppelte Rechnung verhindern Für denselben Wareneingang erneut eine Rechnung erfassen System verhindert eine zweite Rechnung zu demselben Wareneingang.

Rollen und Berechtigungen

Nr. Testfall Schritte Erwartetes Ergebnis
RB-01 Lager darf Wareneingang erfassen Rolle Lager wählen → Bestellung öffnen Button Wareneingang erfassen ist sichtbar.
RB-02 Management darf kritische Fälle entscheiden Rolle Management wählen → Wareneingang in Klärung öffnen Management kann nach Klärung buchen oder Retoure veranlassen.
RB-03 Unberechtigte Aktion blockieren Rolle Management wählen → direkte Erfassung eines Wareneingangs versuchen Aktion wird blockiert. Es erscheint eine Berechtigungsmeldung.

Audit / Ereignisprotokoll

Nr. Testfall Schritte Erwartetes Ergebnis
AU-01 Ereignisse protokollieren Wareneingang erfassen → Prüfung starten → buchen → Rechnung erfassen → Rechnung übermitteln Alle wichtigen Aktionen erscheinen im Ereignisprotokoll mit Zeitpunkt, Benutzer, Objekt, Aktion und Beschreibung.
